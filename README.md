# lecture_notes — 講義PDFから復習ノートを作る Claude Code スキルと、トークン最適化の記録

大学の講義資料(PDF)から、試験対策用の復習ノート(要点まとめ / 重要用語一覧 / 確認問題と解答 / 根拠ページ番号)を
生成する Claude Code スキルです。同じ作業を v0〜v3b の手順で実装し、**トークン数・コスト換算・時間・品質** を
ベンチマークで比較しました。

## 結果の要約

**LD9(48ページのスライド資料、日英併記、画像134枚)** — Sonnet、各3〜5回の平均

| 版 | やり方 | 合計トークン | v0比 | コスト換算 | v0比 | 時間 | 網羅率 |
|---|---|---|---|---|---|---|---|
| v0 | PDF をそのまま読ませる | 434,620 | – | $0.409 | – | 59秒 | 99% |
| v1 | 事前にテキスト化 | **208,966** | **−52%** | $0.185 | −55% | 42秒 | 98% |
| v2 | ノイズ除去 + 章ごとに要点抽出(同じ文脈で) | 342,243 | −21% | $0.281 | −31% | 79秒 | 100% |
| v3 | 章ごとに Haiku サブエージェント(7個)へ委譲 | 337,038 | −22% | $0.191 | −53% | 50秒 | 99% |
| v3b | サブエージェントを3グループにまとめる | 348,104 | −20% | **$0.185** | **−55%** | **25秒** | 98% |

**LD8〜LD10 をつなげた119ページ** — v1 を基準に比較

| 版 | 合計トークン | v1比 | コスト換算 | v1比 | 時間 | 網羅率 |
|---|---|---|---|---|---|---|
| v1 | 358,787 | – | $0.376 | – | 70秒 | 97% |
| v3 | 738,837 | +106% | $0.394 | +5% | 43秒 | 96% |
| v3b | 437,981 | +22% | **$0.270** | **−28%** | 42秒 | 97% |

根拠ページ番号の付与率は、すべての版で100%。詳細は [bench/report.md](bench/report.md)、各段階の考察は [docs/log.md](docs/log.md)。

### わかったこと
1. **一番効いたのは「PDF を画像として読ませない」こと(v1)。** Read ツールで PDF を読むとページ画像も文脈に入る。
   テキスト化だけで v0 比 −52%。
2. **エージェントのコストは「文脈の大きさ × 呼び出し回数」で決まる。** 合計トークンの約8割は、毎ターン同じ文脈を
   読み直すキャッシュ読込。v2 は入力を14%減らしたが、ターン数が約3倍になって逆に増えた。
3. **分割は「別の文脈で処理して、小さな結果だけ持ち帰る」ときに初めて効く。** ただし細かく分けすぎると、戻ってくる
   要約の合計が原文と同じくらいになる(v3, 119ページで v1 より高い)。3グループにまとめた v3b は、長い資料で v1 比 −28%。
4. **トークン数とコストは一致しない。** キャッシュ読込は通常入力の約1/10、Haiku は Sonnet より安い単価で換算されるので、
   「トークンは増えたがコストは下がった」(v3b)、「トークンは2倍だがコストは+20%」(v3 のばらつき)が起こる。両方で比べる必要がある。
5. **固定オーバーヘッド(約3.4万トークン)が下限になる。** 短い資料では、どの工夫をしても「呼び出し回数 × 固定分」で頭打ちになる。

## 構成

```
.claude/
  skills/review-notes/
    SKILL.md            入口。引数でバージョンを選び、versions/<版>.md だけを読む
    versions/v0〜v3b.md 各バージョンの手順
    extract.py          PyMuPDF でページ単位テキスト化・ノイズ除去・章分割・グループ化
    template.md         ノートの出力形式
  agents/chunk-summarizer.md  v3/v3b 用サブエージェント(Haiku, Read のみ)
  settings.json         ベンチを非対話で実行するための許可ルール
bench/
  run_bench.py          claude -p で実行し、トークン・時間・品質を results.csv に追記
  check_quality.py      重要用語の網羅率と、根拠ページ番号の付与率をチェック
  make_report.py        results.csv → report.md
  keywords/             重要用語リスト(1行1語、| で表記ゆれ)
docs/log.md             各段階の「何を変えたか・なぜ減った/減らなかったか」
samples/                動作確認用の自作サンプルPDFと生成スクリプト
```
講義PDF(`lectures/`)と生成ノート(`notes/`)は著作権の都合でリポジトリに含めていません。

## 使い方

前提: macOS / Python 3.9+ / [Claude Code](https://claude.com/claude-code)(Pro プランで動作確認)/ v0 を使う場合は poppler(`brew install poppler`)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python samples/make_sample.py      # サンプルPDFを生成(同梱済み)
```

一度 `claude` を対話モードで起動し、このフォルダを信頼(trust)しておく。`.claude/settings.json` の許可ルールは、信頼済みのフォルダでしか有効にならない。

**ノートを作る**(Claude Code の中で):
```
/review-notes v3b lectures/<講義>.pdf notes/<講義>.md
```

**ベンチマーク**:
```bash
.venv/bin/python bench/run_bench.py --baseline                                   # 固定オーバーヘッド
.venv/bin/python bench/run_bench.py --version v1 --pdf lectures/<講義>.pdf       # 3回(ばらつき>20%なら5回)
.venv/bin/python bench/make_report.py
```

## 測定方法
- `claude -p --output-format json --model sonnet --permission-mode acceptEdits --strict-mcp-config` で、毎回新しいセッションを使う
- **合計トークン** = JSON の `modelUsage` を全モデル分合算(入力 + 出力 + キャッシュ作成 + キャッシュ読込)。サブエージェント(Haiku)分も含む
- **コスト換算** = `total_cost_usd`(API 価格での参考値。Pro プランでは請求されない)
- **網羅率** = 重要用語リストのうちノートに含まれる割合(NFKC 正規化・大文字小文字無視の部分一致)
- **根拠付き率** = 要点・用語・解答の各項目に `(p.N)` が付いている割合(範囲外のページ番号も検出)
- 同じ版の3回で合計トークンの (最大−最小)/最小 が 20% を超えたら、5回に増やす

## 限界
- 資料は1科目(論理回路設計)のスライドだけ。文章中心の資料や、図が本質的な資料では結果が変わる可能性がある
- 網羅率は単純な部分一致なので、説明の正しさや問題の質までは測れていない
- モデルの振る舞い(ターン数、サブエージェントの同期/非同期)で、同じ手順でも結果がばらつく
